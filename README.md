# NEXFORGE — AI-Powered Industrial Intelligence

**Predict • Detect • Explain • Act**

NEXFORGE is a software-only hackathon prototype of an AI-assisted smart-factory command center.
It detects unusual machine behaviour, inspects product images for visual anomalies, combines the
signals into a transparent risk level, explains why an alert happened, and recommends the next
inspection step. An inspection ticket workflow stores outcomes in SQLite.

> **Hackathon prototype.** All factory data is simulated. Real industrial deployment requires
> representative factory data, model validation, safety review, and integration testing.

## Problem
Factories generate many sensor and quality signals, but operators often see them in isolation.
Problems are found late, and the reasons behind an alert are unclear.

## Solution
NEXFORGE joins machine health, product quality, and production data in one view. Each alert
carries its evidence, a confidence level, and a rule-based risk score that anyone can audit.

## Features
- **Command Center**: KPI cards, machine status tiles, cross-machine vibration trend, final summary.
- **Machine Health**: simulated temperature, vibration, pressure, RPM, and current per machine; Start Simulation, Inject Anomaly, Reset Simulation; anomaly score chart; "Why did this alert happen?" evidence.
- **Quality Inspection**: image upload or built-in sample images; OpenCV demo pipeline with overlay, defect score, and confidence.
- **Risk-to-Action Engine**: transparent points per signal, risk level, evidence, recommended steps, cross-signal correlation chart.
- **Maintenance**: ticket creation, status updates (Open / In Progress / Completed), inspection outcome recording.
- **Analytics** and **History**: trends, reject rate, alert frequency, ticket status, searchable and filterable tables.
- **Settings / About**: regenerate demo data, retrain the model, upload and validate a sensor CSV.

## Architecture
```
app.py                  Streamlit UI (sidebar pages, session state, router)
modules/
  simulator.py          Virtual factory: sensor + production readings, anomaly injection
  anomaly_detection.py  Rolling-window features + Isolation Forest + evidence builder
  quality_inspection.py OpenCV rule-based demo vision pipeline
  risk_engine.py        Transparent rule scoring -> LOW / MEDIUM / HIGH / CRITICAL
  maintenance.py        Inspection ticket workflow (SQLite)
utils/
  database.py           SQLite schema and helpers
  data_generator.py     Creates demo CSVs in data/ when missing
  helpers.py            CSV validation and shared constants
tests/test_smoke.py     Smoke tests (includes a Streamlit AppTest page render)
```

## Technology stack
Python, Streamlit, Pandas, NumPy, scikit-learn (Isolation Forest), OpenCV, Plotly, SQLite, joblib.

## How to run
```bash

```
Demo data and the anomaly model are created automatically on first run. No external datasets or hardware are needed.

To run the smoke tests:
```bash
python tests/test_smoke.py
```

## Demo flow (about 3 minutes)
1. **0:00** Command Center shows three machines running normally.
2. **0:30** Open Machine Health, select Machine B, click **Inject Anomaly**.
3. **0:45** The anomaly appears with reasons and a confidence level.
4. **1:10** Open Quality Inspection and click **Sample: scratched product**, then **Run inspection**.
5. **1:45** Open the Risk-to-Action Engine. The signals combine into HIGH risk with a visible point breakdown.
6. **2:15** Click **Create Inspection Ticket**.
7. **2:45** Show Maintenance, Analytics, and History.
8. **3:00** Close with: **FROM ALERT → EVIDENCE → ACTION**.

## Dataset information
`data/` contains simulated datasets generated by `utils/data_generator.py`:
- `machines.csv`: machine list
- `sensor_data.csv`: timestamped sensor readings
- `production_data.csv`: hourly production count, rejects, and reject rate
- `maintenance_history.csv`: past inspection events and outcomes

Nothing here reflects a real factory. To test your own data, use **Settings → Upload real sensor CSV**
with the columns `timestamp, machine_id, temperature, vibration, pressure, rpm, current`.

## AI methodology
- **Anomaly detection**: features over rolling 10-reading windows (mean temperature, temperature std, mean vibration, vibration deviation from baseline, RPM coefficient of variation, pressure and current variation). An Isolation Forest trained on simulated normal behaviour scores each window. A machine is flagged only when at least 2 of its last 3 windows are unusual, which reduces one-off false alarms.
- **Confidence**: based on how many recent windows are flagged and whether enough history exists.
- **Quality inspection**: rule-based OpenCV checks (elongated bright lines, compact blemishes, low outline solidity, missing mid-tone component). This is a demo and is not trained on production images.
- **Risk engine**: fixed, visible points (machine anomaly +30, quality defect +30, repeated anomaly +20, reject rate up ≥10% +10, earlier confirmed issue +10). Bands: LOW < 30, MEDIUM 30–59, HIGH 60–89, CRITICAL ≥ 90.

## Limitations
- Simulated data only, unless a CSV is uploaded.
- The anomaly model describes unusual patterns. It does not predict failures, and it has no measured accuracy on real equipment.
- The vision pipeline is a rule-based demo. It has no measured accuracy.
- Signals that coincide are flagged for investigation. This does not establish causation.
- The single-process SQLite store is intended for a local demo.

## Future improvements
- Train a supervised vision model on labelled production images.
- Use recorded maintenance outcomes to tune alert thresholds and risk weights.
- Add live data streaming from PLC or MQTT sources.
- Role-based access and an audit trail for tickets.
- Calibrated confidence with measured precision and recall on held-out labelled events.
